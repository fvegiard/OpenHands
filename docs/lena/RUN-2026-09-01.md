## Goal

Turn the existing Léna prompt profile into a bounded, testable orchestration layer for OpenHands Agent Canvas, OpenHands Agent Server/Automations, Supabase, Cloudflare webhook ingress, n8n workflows, Tailscale-connected workers, and electrical-company skills.

## Constraints

- This repository owns Agent Canvas UI and integration adapters. Backend agent/tool endpoints belong in `OpenHands/software-agent-sdk`; public skills, automations, and MCP integrations belong in `OpenHands/extensions`.
- No production database migration or public deployment is applied without a reversible migration, backup evidence, and explicit production gate.
- Secrets stay outside Git and are referenced only by environment-variable names.
- Forty-three specialists are a registry of bounded roles. Léna selects a small task-specific team; they are not forty-three permanently running processes.

## Scenarios

1. Registry: exactly 43 specialist definitions validate against a machine-readable schema.
2. Routing: a task selects bounded specialists, a single writer, and an independent reviewer.
3. Webhook: unsigned or replayed events are rejected; valid events become idempotent envelopes.
4. Supabase: additive migration creates a versioned control plane without deleting legacy data.
5. n8n: workflow consumes an authenticated event, calls the orchestrator, records receipt, and routes failures.
6. MCP: electrical tools expose read-first, evidence-cited operations with explicit approval gates for writes.
7. CI: schema validation, unit tests, secret scan, TypeScript checks, and migration lint pass before merge.

## Current findings

- Existing `agents/lena-ia/agent-profile.json` has subagents disabled, concurrency set to one, and no MCP references.
- The current `WORKFLOW.md` demands impossible 100% certainty and conflicts with resilient best-effort execution.
- Supabase `francis-production-core` contains overlapping memory systems and mixed vector dimensions (1024 and 1536).
- Several `bus` and `estimation` tables have broad authenticated privileges with RLS disabled.
- Registered remote machines were offline during the initial audit, so no VM execution has yet been proven.

## Now

Build the source-controlled control-plane package and CI on this branch. Keep external deployments disabled until their real runtime and credentials can be verified.
